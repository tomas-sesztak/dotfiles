# Personal dotfiles repo
## Goal
- manage all personal dotfiles
- deploy to **$HOME** using GNU Stow
	- use script `setup.sh [deploy|undeploy]`
	- deploy redeploys (unstow & stow)
	- stow manages directories where possible, instead of single files

## Rules
- CLAUDE.md / AGENTS.md: Goal and Rules are managed by user, other sections by agents
- update README.md when hotkeys are changed
- test every change, note tools used
- don't read color themes unless instructed to

## Current State
- `setup.sh [deploy|undeploy] [--no-claude]`: auto-discovers each top-level dir under `stow_modules/` as a Stow package, runs `stow -R`/`stow -D` (with `-d stow_modules`) against `$HOME`. `--no-claude` skips the `claude/` package — avoids unlinking `~/.claude` mid-session when testing other packages live.
- Packages (all under `stow_modules/`):
	- `claude/` → `~/.claude` (whole dir stowed). Holds real runtime/secret state alongside tracked config; `.gitignore` allowlists via `stow_modules/claude/.claude/**` then `!`-negates tracked files (`CLAUDE.md`, `settings.json`, `statusline-command.sh`, `hooks/herdr-agent-state.sh`, `skills/*/SKILL.md` — nested files need their dir `!`-negated too). `hooks/herdr-agent-state.sh` comes from `herdr integration install claude` (session-identity hook for herdr's pane labels/notifications, wired into `settings.json`'s `hooks.SessionStart`); reinstalling overwrites it, but it's tracked for reproducibility.
	- `copilot/` → `~/.copilot` (whole dir stowed). Tracks two files: `settings.json` (Copilot CLI settings, e.g. vim editor mode and footer fields) and `copilot-instructions.md`, the latter checked into git as a relative symlink to `../../claude/.claude/CLAUDE.md` — same trick as the repo-root `AGENTS.md -> CLAUDE.md` symlink, one level deeper. Resolves regardless of stow deployment state since it's relative within the repo tree; keeps GitHub Copilot CLI's global instructions (`~/.copilot/copilot-instructions.md`) in sync with Claude's without duplicated content.
	- `nvim/` → `~/.config/nvim` (whole dir stowed, fully tracked — no runtime state here, no allowlisting needed). Every plugin/LSP server checks its external binary deps on startup via `lua/tomas-sesztak/core/deps.lua` (`vim.fn.executable`, deferred `vim.notify` on ERROR — never blocks startup). `plugins/fzf.lua` and `plugins/tmux.lua` warn only; `core/lsp.lua` gates `vim.lsp.enable()` per server on its primary binary (`cmd[1]`) being present, and separately warns on missing secondary tools declared via each `lsp/*.lua` file's own `deps` field (e.g. `shellcheck` for `bashls` — linting only, no formatter wired in).
	- `bash/` — stows `.bashrc` only (no shared subdir to stow as a whole). `.bash_profile`/`.bash_logout` remain unmanaged; `.bash_history` excluded (runtime state).
	- `tmux/` → `~/.tmux.conf` + `~/.tmux` (whole dir stowed). Fully tracked, no runtime state. `~/.tmux.conf` sources `~/.tmux/plugins/init.conf` (mirrors nvim's `plugins/init.lua` aggregator), which sources each plugin file in `.tmux/plugins/`. First plugin: `vim-integration.conf`, holding the `C-h/j/k/l` pane-movement bindings that detect a running (n)vim pane and forward the keys to it instead of switching tmux panes. `<prefix>+z` toggles fullscreen (zoom) on the active pane (`bind-key z resize-pane -Z` in `.tmux.conf`, alongside the other pane/window bindings) — an explicit rebind of tmux's own default `z` binding, kept explicit for discoverability alongside the repo's other custom bindings; the zoomed state shows via the `Z` flag already present in `window-status-*-format`'s `#F`. `status-left` shows a vi-mode indicator after the session name: tmux copy-mode (NORMAL/VISUAL) takes precedence, else the zsh line editor's mode from pane option `@vimode`, which `zsh/.../vi-mode.zsh` sets via ZLE hooks and unsets while a command runs (indicator hidden). `word-separators` omits `.` so mouse double-click selects whole IPs. `window-status-format` hides windows whose `@repo` (git common dir, set by `zsh/.../tmux-repo.zsh` and the agent scripts) differs from the active window's, mirrored to session option `@active_repo` by hooks; worktrees share their main checkout's key.
	- `vim/` → `~/.vimrc` + `~/.vim` (whole dir stowed). Fully tracked, no runtime state. `~/.vimrc` sources `~/.vim/config/{deps,fzf,tmux}.vim`; `tmux.vim` defines `TmuxMove()` (mapped to `C-h/j/k/l` in `.vimrc`), which falls back to `tmux select-pane` at the split edge — tmux only, no herdr fallback.
	- `zsh/` → `~/.config/zsh/functions` + `~/.config/zsh/completions` (whole dirs stowed). `~/.zshrc` is user-owned, not tracked; `setup.sh deploy` appends a `source <repo>/…/functions/init/init.zsh` line if missing (replacing a stale stowed `~/.zshrc` symlink). `init.zsh` prepends Homebrew paths (incl. gnu-sed's `gnubin`) on macOS; `options.zsh` holds global env exports (`EDITOR`, `HELM_REPOSITORY_CONFIG`). `init.zsh` globs and sources every `~/.config/zsh/functions/**/*.zsh` file except `init/` and `late/`, then sources `functions/late/*.zsh` last (holds `syntax.zsh`, since zsh-syntax-highlighting must load after all ZLE widgets). Completion files are tracked; regenerate via `generate_completions()` (`functions/completions.zsh`) and commit the diff. `init-agents -a <agent> -p <path>` ensures a window/workspace per top-level git repo under `<path>`, launching `<agent>` in any missing ones. It auto-detects the active multiplexer (herdr checked first via `$HERDR_ENV`/`$HERDR_WORKSPACE_ID`, then tmux via `$TMUX`; herdr mode auto-starts the herdr server if needed) and errors if run outside both. `fork-agent -a <agent> -w <name> [-c "<cmd>"]` forks the current repo into a new git worktree and starts `<agent>` there, auto-detecting the multiplexer like `init-agents` (herdr checked first, then tmux). Under herdr, the worktree is created/managed via `herdr worktree create` (repo resolved from `$HERDR_WORKSPACE_ID`) and `<cmd>` is sent via `herdr agent prompt` once the agent is running. Under tmux, the worktree is a plain `git worktree add` at `<parent-of-repo>/git-worktrees/<name>`, opened in a new (unfocused) tmux window named `<name>`; `<cmd>`, if given, is passed as a trailing launch argument to `<agent>` instead (no send-after-the-fact mechanism there). Both take `-h`/`--help`. Each script's tmux/herdr implementation function (`_fork-agent-tmux`, `_fork-agent-herdr`, `_init-agents-tmux`, `_init-agents-herdr`) lives in its own file under `functions/tmux/` or `functions/herdr/`; the top-level `fork-agent.zsh`/`init-agents.zsh` files hold only the dispatcher and `-help` function. Wherever a repo/worktree-derived name is used as the actual agent identity — herdr's `agent start`/`agent get`/`agent prompt` name, or the `-n`/`--name` given to claude/copilot — both scripts first run it through `_agent-sanitize-name` (`functions/helpers/_agent-sanitize-name.zsh`, shared by both), which lowercases it, maps disallowed characters to `-`, strips leading non-letters, and truncates to 32 chars, matching herdr's agent-name rule (`^[a-z][a-z0-9_-]{0,31}$`). Workspace/window labels and git branch names themselves are left as the original, unsanitized name. Both tmux impls tag new windows with `@repo` via `_git-repo-key` (`functions/helpers/`). `cleanup-agents [-n]` closes windows/workspaces for agents running in linked worktrees of the current repo (never the main checkout) once the agent is idle/done and the worktree has no uncommitted changes (untracked files count as dirty too), removing that worktree checkout as part of closing; under herdr it uses `herdr agent list`'s `agent_status` to find idle/done worktree agents and a single `herdr worktree remove --workspace <id>` call to close and delete, while under tmux (which has no idle/working signal) a window is only closable once none of its panes are still running `claude`/`copilot`. `-n`/`--dry-run` prints the same decisions without changing anything; its `_cleanup-agents-tmux`/`_cleanup-agents-herdr` sub-implementations live alongside fork-agent/init-agents' under `functions/tmux/`/`functions/herdr/`.
	- `homebrew/` → `~/.Brewfile` (single file; `brew bundle --global` default). `brew_update` (`zsh/.config/zsh/functions/brew.zsh`) syncs Homebrew to it: installs/upgrades listed packages and deps, uninstalls unlisted ones, cleans up.
	- `herdr/` → `~/.config/herdr` (whole dir stowed). Same allowlist trick as `claude/`: only `config.toml` tracked; rest (`session.json`, `*.log`, `*.sock`, `.plugins.lock`) is untracked runtime state.
- No build/lint/test tooling; verify via `./setup.sh deploy` + `ls -la` on the resulting symlinks.
